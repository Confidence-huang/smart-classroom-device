# EcoVision 算法第一版实施计划（2026-11-18）

**Goal:** 为 11 月 20 日本地闭环交付独立、可回放的 C99 算法，不修改冻结契约或驱动。

**Architecture:** 输入携带本地采样时间、来源、模拟标志和驱动有效性；通用三点中值仅用于评价。AUTO 使用范围检查后的原始温度，复现契约的占用、回差、持续确认和故障降级；外部控制权管理器提供已仲裁模式与真实输出。

**Tech Stack:** C99 整数、MSVC 主机测试、AC6 Cortex-M4 对象编译、Python 离线比较。

## 设计取舍

- 原值无滤波：延迟最低，但评价噪声较大；保留为控制兼容基线。
- 三点中值：可去单个孤立尖峰，阶跃延迟约一个采样周期；作为评价默认方案。
- 三点均值／一阶低通：对白噪声有效，但会扩散尖峰／延长阶跃尾部；使用明确标注的合成数据比较后再决定。
- 不增加综合评分、PMV、人数热负荷估计、自动开窗、PWM 调速或红外指令。

## 顺序与验证

1. 创建 C 行为测试并先运行，确认缺少实现导致失败。覆盖新鲜度、异常恢复、占用、回差、手动接管、回绕、消抖。
2. 实现 algorithms/ecovision_algorithm.h 和 .c；运行相同测试并修正。
3. 实现 CSV 回放工具与 Python 合成数据比较；重复回放比对确定性，保存指标与数据标记。
4. AC6 以 Cortex-M4 编译独立对象，记录代码／状态开销；不链接或烧录现有固件。
5. docs/modules/algorithms.md 记录来源、参数、集成、期限和接口建议；tests/algorithms/RESULTS.md 分开报告软硬件证据。

公共接口由总控维护。计划放在本模块内，避免改写总控的计划文档。当前工作区无 .git，独立目录内直接实施，不创建或提交仓库。
