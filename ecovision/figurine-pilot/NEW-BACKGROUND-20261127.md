# 新背景小人模型重训练与 K230 部署

沙盒改用稳定背景、磁铁固定小人后，原模型出现漏检与背景误检。本次归档 V1～V4 四轮训练，目标为 0～20 人；设备默认入口更新为已在现场运行的 V4。这里的 V4 指 **2026-11-27 新背景版**，不是历史 `optimization-v4` 模型。

每轮读取包含重复采样，不能解释为独立图片数量。V1 含12张旧训练图片回放；其余版本保留旧拆分。用户核对后的补拍为16人；17人文件夹第一张仍为18人，均按确认结果标注。19人与20人文件夹各19张，其中19张训练、5张验证、14张测试；19→20过渡组及另一20人连续布局按组留出。

训练设备 RTX5070 Laptop GPU；单类别 `figurine`、320×320、batch8、AdamW、AMP关闭。完整参数、曲线、权重SHA见各阶段 `selected/` 与 [版本清单](versions-20261127.json)。`dataset-manifest.json` 包含所有实际图片的SHA、拆分、YOLO标签（包括回放图片），不提交原始照片。脚本是当日流程归档，缺少原图、预标注中间数据或前序权重时不能直接重跑；恢复说明见各阶段 README。

## 已部署到 K230

- 已加载的模型：[figurine_newbg_v4_20261127.kmodel](background-20261127-count19-20/deployment/figurine_newbg_v4_20261127.kmodel)，3490672字节，SHA256 `7326229cd117498c9ca0f08420233da854ff40741a62653970f6de5a0650cfd7`。
- 板端路径 `/sdcard/kmodel/figurine_newbg_v4_20261127.kmodel`；运行入口仍为 `/sdcard/ecovision_uart/figurine_uart.py`。先上传模型，再更新入口；模型与入口必须配套。
- nncase / nncase-kpu 2.11.0，161张训练图做uint8 Kld校准；RGB float32/255，320×320，左上对齐、底部/右侧128填充。板端固件CanMV v1.8-66-g2d060be。ONNX输出 `[1,5,2100]` 已检查。
- 摄像头sensor_id2、640×480；板端最终 **conf0.50 / NMS0.45 / max_boxes60**。原UART发布器、boot ledger、无效状态与0～20范围校验不改，不强行截断到20。
- 原模型保留。板端旧程序备份 `/sdcard/ecovision_uart/figurine_uart.before_newbg_v4_20261127.py`。已有 `/sdcard/main.py` 原字节不变，仍加载同一入口。

默认conf0.35在当前20人场景误检顶部线缆，部分帧计为21并按原逻辑报告无效。定位后用当前实物场景校准conf0.50：45秒诊断中完整600帧为597帧20人、1帧19人、2帧无效；20次每30帧抽样虽全为20，不能掩盖帧间错误。运行约14FPS。**板端0.50是现场校准设置，不能沿用PC0.35的30/35分数。**

## 复核、恢复与后续

PR内入口只改模型路径、阈值、最多框数与启动banner；其余代码与已部署源归一化空白后逐字相同。仓库入口使用正常换行，板端原文件存在额外空行，因此原始文件SHA不相同；归档 `figurine_uart_deployed.py` 保留板端字节校验基准。

回退：停止当前识别，备份现入口，再以板端 `figurine_uart.before_newbg_v4_20261127.py` 恢复同名入口并重启；或回退PR的入口修改并使用原 `figurine_multi.kmodel`。不改boot ledger或STM32私有配置。

后续仍需独立采集不同摆法、0～20人视频与板端长测，尤其是原18人遮挡场景；量化/现场参数结果与浮点结果分别验收。本PR不修改STM32固件、协议契约、云端或网页。

本地检查与当前提交CI结果以PR为准。完整Linux主机脚本在本机WSL启动时因缺少`cc`未执行C测试；不以此称为C测试失败或已通过。现有K230/协议主机检查另行执行，云端工作流执行完整主机检查。

PR整理阶段验证：现有K230主机33项、公共协议18项通过；四版权重SHA、完整标签数量/几何/跨集合SHA隔离、最终kmodel SHA及仓库入口与实机源的空白归一化一致性均通过；归档Python AST检查通过。没有重新训练或新增硬件验收。
