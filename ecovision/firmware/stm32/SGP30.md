# SGP30 室内空气质量采集

F413 环境任务通过 I²C1 读取 SGP30 的 TVOC（ppb）和等效 CO₂（eCO₂，ppm），每 5 秒输出一条 `[AIR]` 串口日志。eCO₂ 是传感器根据气体响应估算的等效值。现有舒适度算法中的实测 CO₂ 输入仍保留给适配的传感器。MQTT 遥测、开窗和风扇控制策略沿用现有版本。

## 接线与供电

| 信号 | F413 连接点 |
| --- | --- |
| SCL | PB8／D15／CN7-2 |
| SDA | PB9／D14／CN7-4 |
| GND | 与 F413 共地 |
| VIN/VCC | 按手上转接板的型号和说明核对；接入前确认 SDA/SCL 与 3.3 V 总线兼容 |

SGP30 地址为 7 位 `0x58`，与同总线的 AHT20 `0x38` 和 BH1750 `0x23` 或 `0x5C` 无地址冲突。芯片裸片的供电范围为 1.62–1.98 V；只有明确带合适稳压和 I²C 电平转换的模块，才按模块说明接到 3.3 V 总线。核对现有上拉和转接板上拉后再接线。[Sensirion SGP30 数据手册](https://sensirion.com/media/documents/984E0DD5/61644B8B/Sensirion_Gas_Sensors_Datasheet_SGP30.pdf)

## 数据有效性

环境任务以 1 秒为目标周期，在同一个任务中依次访问总线上的传感器。SGP30 初始化后继续测量，但前 15 秒返回的固定值只作为暖机过程。驱动读取两个数据字及各自的 CRC，检查单位对应的输出范围。样本超过 2.5 秒后，读取环境快照时将其标为无效。

| 串口字段 | 含义 |
| --- | --- |
| `valid=1 tvoc_ppb=… eco2_ppm=…` | 当次数据通过通信、暖机、CRC 和范围检查 |
| `valid=0 status=1` | 启动暖机，数值暂不输出 |
| `valid=0 status=-1` | SGP30 通信异常或等待重新探测，探测间隔 5 秒 |
| `valid=0 status=-2` | CRC 失败，丢弃当次数据 |
| `valid=0 status=-3` | 任一数值超出传感器输出范围，丢弃当次数据 |

目前用于室内空气质量趋势观测。绝对湿度补偿、长期基线保存和实板比对留待现场稳定性验证。

## 验证

- 运行设备仓 `ecovision/firmware/stm32/tests/run_host_ci.sh`。SGP30 用例模拟 I²C，覆盖初始化、周期测量、暖机、解码、双 CRC、异常范围、退避重试和时钟回绕。
- 实板先确认模块确切型号和供电电平，查看 `[AIR]` 由暖机变为有效，并同时观察 `[ENV]`、`[LIGHT]` 和 4G 遥测。另一次断电后移除 SGP30，再启动核对空气质量无效、现有温湿度与光照仍更新。
- 用于提交验收时保留固件提交、HEX SHA256、模块型号和串口日志。
- **2026-11-28 实板初验（NUCLEO-F413ZH + COM4）**：烧录 AC6 构建 HEX（SHA256 `4d4c10cf85c0adae6b27cfa05673a140822b848c3d180a767a5bc92dfcf72278`，仅擦写 sectors 0–3 保留 `0x08160000` 私有配置区），上电 35 s 串口观测确认：`1.05s / 7.07s / 12.01s` 输出 `[AIR] source=SGP30 valid=0 status=1`（暖机），`17.01s / 22.01s / 27.01s / 32.01s` 持续输出 `[AIR] source=SGP30 valid=1 tvoc_ppb=0 eco2_ppm=400`；同总线 AHT20（`[ENV] th_valid=1 err=0`）、`[ZJ-IR] UART5 ADDRESS_OK`、K230 视觉与 4G 遥测（`PUBACK seq=0..7`）均正常。拔除 SGP30 后的断线降级与呼气/酒精刺激变化待按需补测。
